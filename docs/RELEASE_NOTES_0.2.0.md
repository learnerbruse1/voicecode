# VoiceCode v0.2.0 — Windows 安装版、三语界面与稳定性升级

## 主要更新

### Windows 安装程序

- 新增标准 Windows x64 安装程序，可自由选择安装目录。
- 安装包包含 VoiceCode 核心依赖和独立的 Python/pip 运行时，普通用户无需提前安装 Python。
- 默认采用当前用户安装，不需要管理员权限。
- 模型、可选依赖和下载缓存统一存放在 `<安装目录>\runtime`。
- 支持自定义路径安装、覆盖安装、卸载后重装以及已有模型缓存复用。
- 新增应用程序图标，并应用于主程序、安装程序、桌面快捷方式和 Web UI。
- 修复安装版静态资源缺失导致桌面窗口显示 HTTP 404 的问题。

### 模型下载与运行

- 首次启动时不再强制下载固定的 `base` 模型，而是等待用户完成模型选择。
- 启动时会正确加载用户已配置的模型。
- 完整区分“已缓存”“部分下载”和“未下载”状态。
- 模型下载界面会显示已下载大小、预计大小、进度、速度、耗时和停滞状态。
- 增加网络超时、磁盘空间不足、目录权限和缓存损坏等结构化错误提示。
- 支持复用已有 faster-whisper / Hugging Face 模型缓存。
- 默认禁用容易出现区域性超时的 Hugging Face Xet 下载路径，并提供可访问端点回退。
- 自动检测 NVIDIA CUDA；CUDA 初始化或运行失败时可安全回退到 CPU int8。

### 首次启动与桌面体验

- 新增可恢复的首次启动引导，覆盖界面语言、运行依赖、麦克风、模型和硬件设置。
- 新增英语、简体中文和日语界面，并修复中日文乱码和语言切换持久化问题。
- 优化模型管理页面、硬件状态摘要、下载进度、弹窗焦点和长任务遮罩。
- Windows 重复启动时会唤醒已有窗口，不再产生端口冲突报错。
- 支持搜索、筛选、复制、删除和导出转写历史。
- 支持导出诊断信息，方便提交问题和排查运行环境。

### 扩展与依赖管理

- 扩展页面现在支持启用、禁用和配置保存。
- 支持一键安装必需依赖，并显示安装进度、日志和状态。
- 依赖任务支持持久化、取消、超时、磁盘空间检查和进程树终止。
- 可选依赖安装在隔离目录中，不会修改系统 Python 环境。
- Silero VAD、pyannote 说话人分离和 NeMo 标点恢复提供按需加载适配器。

### 本地安全与稳定性

- 本地服务仅绑定到 `127.0.0.1`。
- 写操作使用每进程本地 API 令牌保护。
- 增加 Host/Origin 校验、CSP、防嵌套和内容类型保护响应头。
- 配置更新和历史记录修改在并发请求下保持原子性。
- 非空 JSON 请求体必须是有效对象，错误请求不会触发副作用。
- 启动时会验证 `/health` 返回的 PID，避免连接到错误或残留的本地服务。

### 内置扫雷

- 内置经典扫雷，提供初级、中级和高级三种难度。
- 高级模式为 `16 × 30`，包含 99 个地雷。
- 支持首次点击安全区、插旗、数字联动展开、计时和胜负状态。
- 扫雷界面支持英语、简体中文和日语。
- 本版本不包含纸牌游戏内容。

## 安装方法

1. 下载 `VoiceCode-v0.2.0-Windows-x64-Setup.exe`。
2. 可选：使用上方 SHA-256 校验安装包完整性。
3. 运行安装程序并选择安装目录。
4. 启动 VoiceCode，按照首次启动引导选择语言、麦克风、模型和运行设备。
5. 首次使用所选模型时需要联网下载；模型下载完成后可在本地离线转写。

PowerShell 校验命令：

```powershell
Get-FileHash .\VoiceCode-v0.2.0-Windows-x64-Setup.exe -Algorithm SHA256
```

## 从旧版本升级

- 可以直接运行 v0.2.0 安装程序安装或覆盖现有版本。
- 旧配置会自动迁移到当前配置结构，无需手动修改。
- 已下载模型可以继续复用。
- 配置、日志和转写历史保存在当前用户的配置目录中。
- 卸载程序会删除安装器管理的程序文件，但之后下载的模型、依赖和缓存可能保留在 `<安装目录>\runtime`，方便重新安装后继续使用。
- 如果需要彻底删除，请在卸载后手动删除剩余的安装目录。

## 已知事项

- 当前 Windows 安装程序未进行代码签名，可能触发 Windows SmartScreen 提示。
- 安装包不预置 Whisper 模型，首次下载模型需要网络连接和足够的磁盘空间。
- NVIDIA GPU 模式需要与 CTranslate2 兼容的 CUDA/CuDNN 运行环境；不满足条件时建议使用自动或 CPU 模式。
- 不同麦克风、声卡和全局快捷键环境可能受到系统权限或安全软件影响。
- macOS 和 Linux 当前建议继续通过 Python 源码方式运行。
