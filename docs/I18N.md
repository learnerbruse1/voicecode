# Internationalization Guide

The refreshed v0.2.0 Windows installer pass on July 25, 2026 verified that the installed English, Chinese, and Japanese catalogs each contained 371 entries, included the Minesweeper-only labels, and were packaged without corrupted icon/text assets. The full interactive language-rendering pass was completed on July 24, 2026. See [RELEASE_VALIDATION_0.2.0.md](RELEASE_VALIDATION_0.2.0.md).

VoiceCode supports `en`, `zh`, and `ja`. UI catalogs are external JSON files loaded at runtime; backend logs, exceptions, API errors, and script output remain English.

## Source files

The authoritative packaged catalogs are:

- `src/voicecode/static/i18n/en.json`
- `src/voicecode/static/i18n/zh.json`
- `src/voicecode/static/i18n/ja.json`

Root `static/i18n/*.json` files are source-tree mirrors and must remain byte-identical. `static/js/i18n.js` is an ES Module containing only catalog loading and validation logic; translations must not be embedded back into JavaScript.

## Loading behavior

1. `app.js` waits for `initializeI18n("en")` before initial translation.
2. `loadConfig()` reads `ui_language`, loads that catalog, and reapplies translations.
3. A live language change loads the catalog before updating DOM text.
4. Missing keys fall back to English, then to the key itself.
5. Invalid/non-object catalog payloads reject bootstrap with a visible frontend error.

Catalog URLs use `/static/i18n/<language>.json`, so package data and desktop bundles must include the files. The game catalog keys describe only Minesweeper (`nav_games`, difficulty labels, timer, mine count, win/loss); card-game keys are not part of the UI contract.

## Adding or updating copy

1. Add the English key first.
2. Add semantically equivalent Chinese and Japanese values in the same change.
3. Use `data-i18n`, `data-i18n-title`, `data-i18n-aria`, or `data-i18n-placeholder` for static markup.
4. Use `t("key")` for dynamic content.
5. Do not concatenate grammar-sensitive fragments when a complete sentence key is possible.
6. Run the catalog parity and static synchronization tests.

## Validation

```powershell
python -X utf8 -m pytest -q
Get-ChildItem src/voicecode/static/js/*.js | ForEach-Object { node --check $_.FullName }
```

Tests verify that non-English catalogs contain every English key and that both static trees match.

## Layout checklist

- Allow labels/buttons to wrap.
- Avoid fixed-height translated containers.
- Check onboarding, extension forms, navigation, model cards, and error/progress dialogs in all languages.
- Keep technical identifiers, model names, units, and user/device data untranslated unless a display label is provided.

After catalog changes, run `python -X utf8 tools/sync_static.py` and then the catalog parity tests.

## Encoding policy

All catalogs and static assets are UTF-8 without replacement characters. Dynamic game and error states use catalog keys instead of emoji-dependent labels so English, Simplified Chinese, and Japanese render consistently in Windows WebView. Catalog key parity is enforced by tests.
